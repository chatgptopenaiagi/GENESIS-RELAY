# Engineering letters and laboratory reconstruction

Relay captures documented engineering knowledge, not hidden model thoughts. `knowledge.capture` reads only the selected project documentation, literal experiment definitions and the explicitly selected Sentinel generation. It generates nine readable, evidence-indexed documents: START-HERE, purpose, human intent, architecture, decisions, current state, known problems, next steps and the evidence index.

Each significant claim has a stable ID, classification and source file/hash. Classifications distinguish operator requirements, new source observations, historical reports, engineering inferences, untested proposals and unknown context. Missing conversations remain missing. Catalogue extraction uses AST literals; it never imports the project's code during inspection. Scientific descriptors remain labelled computations rather than measured properties.

Exact source environment metadata is collected through the selected absolute interpreter in isolated mode. Direct URL credentials/query tokens are removed. The Sentinel adapter filters to the laboratory's environment, relevant capabilities and project record; other projects/environments are not exported as a global destination inventory. Source metadata never establishes destination capability verification.

## Reconstructing the demonstration

The trusted receiver creates a new working project and immutable source evidence. `laboratory.adapt_project` refuses the original laboratory installation. On the available Linux route it creates a new project-owned `.relay-venv` using explicitly reused compatible destination system packages; no source ARM64 environment is copied and no global dependency transaction occurs. It changes the working server only: port, local Host/Origin allowlist, worker interpreter and destination/capsule execution context. The scientific engine, catalogue and worker source remain byte exact. All adaptations have before/after hashes and a readable diff.

Call `receiver.record_adaptation` after adaptation and before new experiments. This is the common destination baseline for returning later work. New scientific results then remain new work, separate from immutable historical receipts.

`laboratory.acceptance` starts the owned relocated service, executes a matrix product, symbolic differentiation, benign molecule descriptors/rendering and integration/plot/report, verifies SQLite/run-artifact relationships, restarts only the owned idle service and checks old rows/new outputs persist. Each fresh receipt records route, destination identity, interpreter, timestamps and source capsule identity/digest. Missing requirements and skipped experiments remain separate and prevent an unqualified READY result.

Native Windows and WSL are separate routes. Linux parsing of the PowerShell receiver is not native Windows acceptance. The original laboratory service uses `fcntl`, `resource`, Unix process groups and shell helpers, so native Windows requires explicit compatibility work and actual execution. The current adapter blocks native Windows rather than silently pretending those facilities exist. WSL qualification requires actual WSL x64. A relocated Linux test is labelled LOCAL_ROUNDTRIP_ONLY.

## Safe source capture

The original service exposes no export/quiescence endpoint. For this project the sender must verify no scientific job is active, validate owned process identity, briefly stop through the existing project helper, obtain a SQLite database-aware backup, capture referenced results while stopped, verify integrity/relationships, then restart only if it had been running. Parent orchestration owns that source lifecycle action; neither the knowledge adapter nor destination tests stop the original service.

Source credentials, active sessions and PID records are excluded. Destination credentials are generated by the original authentication mechanism in the new private working directory. Source AGENTS remains archived; effective destination guidance points to delivered records and the next bounded mission. No global Codex configuration, authentication or executable is changed.
