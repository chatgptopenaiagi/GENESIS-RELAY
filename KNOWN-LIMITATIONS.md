# Known limitations of experimental 0.1.0

This release preserves separate evidence scopes. Consult the exact commit, hashes, native runner results and public-download acceptance in VERIFICATION-SUMMARY.json and PUBLICATION-VERIFICATION.json. A workflow definition or a package filename is not a passed test.

- The lightweight synthetic laboratory exercises standard-library reconstruction. It does not certify arbitrary software, the private Science Lab's full scientific stack, the operator's personal Windows machine, WSL or a Windows Codex login.
- Project dependencies must be discovered and reconstructed independently. Relay's bundled executable runtime is for Relay; it is not a foreign project's scientific environment. Offline installation of Relay does not imply offline project reconstruction.
- Generic snapshots use SQLite backup and bounded stable-file/entry-set checks. They are not a universal transaction across applications or filesystems. A live application with cross-file relationships needs a verified checkpoint/quiescence adapter. The optional known scientific profile has separate ownership/idle checks.
- Source evidence preserves exact included bytes and logical metadata. Working restoration does not reproduce every ACL, extended attribute, hardlink relationship or directory permission/timestamp semantic. Windows filename mappings may require project-specific adaptation.
- The return protocol compares hashes and applies selected whole regular files. It does not automatically merge text hunks or reconcile new symlinks/empty-directory topology. Guidance and platform adaptations require review.
- Database returns are separate integrity-checked SQLite snapshots requiring manual/logical reconciliation. They are never text merged or blindly substituted for a newer database. Capture a return only while its application is idle or under a checkpoint; SQLite integrity alone is not a cross-file transaction.
- Return application uses per-file replacement, backups and journals, not one atomic operation across all selected files. Interrupted application needs inspection and reviewed rollback. Duplicate import after rollback remains a no-op. Rollback refuses to destroy newer edits.
- Readiness describes stored acceptance at a recorded time, not continuous health monitoring. Later recorded failures invalidate current readiness while prior milestones remain in history.
- Primary format defaults limit ZIP members to 100,000, expanded payload to 8 GiB and individual metadata to 32 MiB, with a finite compression-ratio guard. Return limits are smaller and documented in RETURN-PROTOCOL.md. Exceeding a limit fails explicitly.
- SHA-256 proves agreement with a retained reference, not authenticity or scientific correctness. Optional external signing requires an independently trusted existing key. Known-name/pattern/value privacy checks cannot prove absence of all unknown secrets; capsules can contain private research even after credentials are removed.
- Linux ARM64 under Termux/proot is not a native Android application. Browser viewport tests are distinct from physical touchscreen tests. Windows native, WSL and Linux results must never be interchanged.
- Fresh Codex continuation uses delivered files as context, not a transfer of model memory. Codex executables, authentication and unrelated configuration are never bundled or rewritten. Any unavailable fresh Windows session is reported independently as NOT_RUN.
