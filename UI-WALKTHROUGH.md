# Your visible continuation workflow

Start `relay ui start` (or the extracted `Genesis-Relay.exe ui start`) and use `ui access` in an operator terminal to obtain the local login. Open the actual URL printed by startup. With no configured source, Relay creates an owned synthetic laboratory containing invented data; no author's machine or account is needed.

1. **My projects** explains the selected project's purpose, location and separate continuation stages. A synthetic-demo label distinguishes the example from personal research.
2. **Send my laboratory** shows the full scope, file counts, database handling, dependency references and exclusions before export. Create a capsule only after reviewing the plan.
3. **What is inside this capsule?** shows accounted source, saved work, environment requirements and omissions as readable cards. Search/filter entries, inspect integrity and download the private capsule. A download is not a destination receipt.
4. **Receive and continue** separates Inspect, Plan, Restore, Verify and the known demo's explicit acceptance. Generic projects require reviewed project-specific tests rather than an arbitrary execute button. The source capsule stays unchanged while a new workspace is created.
5. **Engineering letter** presents purpose, human intent, architecture, decisions, current state, known problems, next steps and an evidence index. Historical reports and new observations stay distinct.
6. **Verification results** displays new bound destination checks separately from preserved source results. Windows, WSL, local Linux and synthetic/private scientific scopes are not interchanged. Readiness is a recorded acceptance state, not continuous monitoring.
7. **Return improvements** creates a return proposal. In the demo, the explicit improvement action adds a harmless note before export. Actual application uses preview, selection, conflict refusal and rollback; database snapshots remain separate.
8. **Transfer history** records operations and receipts chronologically. Available, downloaded, restored, tested and ready labels describe different events.

Real screenshots in `docs/screenshots` use only this synthetic demonstration. They are browser captures, not drawings or private-laboratory screenshots. Viewport and physical-device/native-platform scope is recorded with the screenshot verification evidence.

Credentials never appear in screenshots or reports. Imported text is escaped. State-changing requests require authentication, a local Origin and CSRF token; request bodies cannot choose arbitrary filesystem destinations or shell commands. Loopback binding and discovered ports preserve unrelated running applications.
